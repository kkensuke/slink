# slink

[English](README.md) | [日本語](README.ja.md)

`slink` は、TOML ファイルを基に、シンボリックリンク（以下、リンク）を安全に作成・管理する macOS 向け CLI です。

## インストール

```sh
brew install kkensuke/tap/slink
```

または、現在の stable Rust ツールチェーンでソースからビルドします。

```sh
git clone https://github.com/kkensuke/slink.git
cd slink
cargo install --path . --locked
```

## 最初の操作 `slink <target> <link>`

`<target>` は参照先、`<link>` は作成するリンクの配置先です。相対パスは、コマンドを実行するディレクトリ（作業ディレクトリ）を基準に解釈します。

```sh
cd ~
slink -p A/target B/link
```

ホームディレクトリが `/Users/you` の場合、この操作は次のようになります。

- `/Users/you/A/target` を指すリンクを `/Users/you/B/link` に作成し、管理ファイルに登録します。
- `-p` は親ディレクトリ `B` がなければ作成します。参照先の `A/target` は作成しません。
- `B/link` に通常ファイルやディレクトリがある場合は、変更せず競合を報告します。既存のディレクトリの中にリンクを作ることはありません。
- 参照先自体がリンクでも構いません。その場合も、指定したパスを参照先として登録します。

管理ファイルには次の内容が保存されます。

```toml
[[link]]
link   = "/Users/you/B/link"
target = "/Users/you/A/target"
```

登録内容を確認するには、次のコマンドを使います。

```sh
slink list
```

上記の1件だけを登録している場合、次のように表示されます。

```text
1 link

"/Users/you/B/link"
  → "/Users/you/A/target"
```

登録どおりのリンクが存在し、参照先へアクセスできるかを検査するには、次のコマンドを使います。

```sh
slink check
```

存在しない参照先へのリンクも作成できますが、参照先へアクセスできるようになるまで `check` は問題として報告します。

## コマンド

```text
slink [options] <target> <link>
slink --config
slink list
slink check [link ...]
slink fix [options] [link ...]
slink unregister [options] <link ...>
slink remove [options] <link ...>
slink adopt [options] <link ...>
slink scan [options] [directory ...]
```

| コマンド | 役割 |
| --- | --- |
| `slink <target> <link>` | 指定した参照先へのリンクを作成し、登録を追加・更新する |
| `slink --config` | 管理ファイルの場所を表示する |
| `slink list` | 登録内容を表示する。リンクの検査は行わない |
| `slink check [link ...]` | 登録と実際のリンクを照合し、参照先へアクセスできるかを検査する |
| `slink fix [link ...]` | 管理ファイルからリンクを復元する。参照先が異なる既存のリンクの置換には `-f` が必要 |
| `slink unregister <link ...>` | 登録を解除する。リンクの配置先にあるものは変更しない |
| `slink remove <link ...>` | 登録と一致するリンクを削除し、登録解除する。参照先のファイルやディレクトリは削除しない |
| `slink adopt <link ...>` | 既存のリンクから登録を追加・更新する。リンク自体は変更しない |
| `slink scan [directory ...]` | 指定ディレクトリ直下のリンクを探す。省略時は作業ディレクトリを使う |

`check` と `fix` は、リンクを指定しなければ全登録を対象にします。`unregister`・`remove`・`adopt` はリンクの明示指定が必要です。

### 配置先がすでに存在する場合 `slink -f <target> <link>`

| 配置先の状態 | 通常の作成 | `-f` 付きの作成 |
| --- | --- | --- |
| 存在しない | リンクを作成し、登録を追加・更新する | 同じ |
| 参照先のパスが一致するリンク | リンクを保持し、登録を追加・更新する | 同じ |
| 参照先のパスが異なるリンク | 競合を報告する | リンクを置換し、登録を追加・更新する |
| 通常ファイル・ディレクトリなど | 競合を報告し、変更しない | 同じ |

## パス

| 入力・保存値 | ルール |
| --- | --- |
| コマンドに渡すパス | 絶対パス、作業ディレクトリを基準にした相対パス、先頭の `~/` を受け付け、絶対パスに変換する |
| 管理ファイルの `link` / `target` | リンクの配置先 / 参照先。手編集する場合も、両方に絶対パスを指定する |
| 新規作成・復元するリンクの参照先 | 絶対パスで設定する |

引用符で囲んだ `"~/…"` もコマンドに渡せます。管理ファイル内の `~`、変数、シェル式は展開しません。

### 相対パスを参照する既存のリンクを登録する `adopt`

`adopt` は、既存のリンクに書かれた相対パスを、リンクが置かれているディレクトリを基準に絶対パスへ変換して登録します。

例えば、`/Users/you/bin/python3` の参照先が `python` なら、管理ファイルには `/Users/you/bin/python` を保存します。

```sh
slink adopt ~/bin/python3
slink check ~/bin/python3
slink fix ~/bin/python3
```

`check` と `fix` も、参照先のパスを絶対パスに変換してから登録と比較します。一致するリンクは書き換えません。リンクが削除された場合、`fix` は参照先を絶対パスで指定して作り直します。

## 管理ファイル

管理ファイルは通常 `~/.config/slink/links.toml` です。`XDG_CONFIG_HOME` に絶対パスを設定している場合は、`$XDG_CONFIG_HOME/slink/links.toml` を使います。未設定・空・相対パスの場合は通常の場所を使います。

リンクの作成や `adopt` の際、管理ファイルがなければ作成します。`scan` は管理ファイルがなくても実行できます。

管理ファイルを開いて表示または編集するには、次のコマンドを使います。

```sh
open "$(slink --config)"
```

1件の登録につき `[[link]]` ブロックを1つ書き、文字列の `link` と `target` だけを記述します。両方とも絶対パスが必要です。空ファイルは登録 0 件を表します。

`list` は管理ファイルの記載順に登録を表示します。パスが不正な項目や重複した登録も表示するため、内容の検証には `check` を使ってください。`check`・`scan`・変更操作では、管理ファイル全体のパスと重複を検証します。TOML の構文や項目の書き方に誤りがある場合は、`list` でも読み込めません。

| 手編集 | 結果 |
| --- | --- |
| `link` を変更 | 古いリンクは未登録のまま残り、`fix` で新しいリンクを作成できる |
| `target` を変更 | `fix -f` で既存のリンクの参照先を更新できる |
| 項目を追加 | `fix` で不足するリンクを作成できる |
| 項目全体を削除 | リンクは残り、`list`・`check`・`fix` の対象から外れる |

リンクを残して管理をやめるには `unregister` を使います。リンクと登録を両方削除するには、項目を消す前に `remove` を使います。手で変更したリンクに管理ファイルの登録を合わせる場合は `adopt` を使います。

管理ファイル自体がリンクの場合は、その参照先のファイルを更新します。

## オプション

| 短縮形 | 長い形式 | 用途 |
| --- | --- | --- |
| `-c` | `--config` | 管理ファイルの場所を表示 |
| `-f` | `--force` | 作成・`fix`：参照先が異なる既存のリンクを置換 |
| `-p` | `--parents` | 作成・`fix`：不足するリンクの親ディレクトリを作成 |
| `-n` | `--dry-run` | 作成・`fix`・`unregister`・`remove`・`adopt`：書き込まず変更予定を表示 |
| `-R` | `--recursive` | `scan`：サブディレクトリも探索 |
| `-o` | `--format <human\|tsv>` | `list`・`check`・`scan`：出力形式を指定 |
| `-h` | `--help` | ヘルプを表示 |
| `-V` | `--version` | バージョンを表示 |

短縮形は `-np` のように連結できます。`--config`・`--help`・`--version` は単独で使います。

コマンド名やオプション名と同じ名前のパスを渡す場合は、前に `--` を付けます。

```sh
slink -- list ./list-link
slink check -- -link
```

最初のコマンドは、作業ディレクトリにある `list` というファイルを参照先にします。2つ目は、`-link` という名前の登録済みリンクを検査します。

## リンクを探す `scan`

```sh
slink scan
slink scan -R ~/projects
slink scan ~/links
```

- `scan` は指定ディレクトリの直下を探索します。ディレクトリを省略すると作業ディレクトリを使い、`-R` を付けるとサブディレクトリも探索します。ディレクトリへのリンクは表示しますが、その中へは入りません。探索開始ディレクトリにもリンクは指定できません。
- `check` が登録済みのリンクを検査するのに対し、`scan` は未登録のリンクも探せます。見つかったリンクを管理するには `adopt` で登録してください。ディレクトリへのリンクを登録しても、その中にあるリンクは自動登録されません。

## 出力

既定の `human` 形式では、`scan` の結果を登録済み・未登録に分け、それぞれ問題のあるリンクを先に表示します。`check` で問題がなければ `OK N links` と表示します。

`human` のリンク配置先・参照先・親ディレクトリのパス欄は、二重引用符と JSON エスケープを使って表示します。絶対パスはホームディレクトリを省略せず、相対の参照先は相対表記のまま表示します。途中の `/./` や重複する区切りを整理し、`..`、先頭の `./`、先頭の `/` の個数は保持します。末尾の `/` と `/.` は区別して残し、末尾で連続する `/` は1つにまとめます。

この整形は表示だけに適用し、保存されたパスや symlink、コマンド引数での `~/` の受け付けは変更しません。名前に文字として含まれる `~` もそのまま扱います。`--config` はコマンド置換で使えるよう、引用符なしの絶対パスを出力します。

色を無効にするには、環境変数 `NO_COLOR` を設定するか、`TERM=dumb` を指定します。

### 変更結果とプレビュー

リンクの作成・登録・登録解除・削除・復元では、配置先と操作結果を表示し、その次の行に登録された参照先を示します。

`fix` は、変更したリンクと参照先に問題があるリンクを表示し、正常で変更不要なリンクは件数にまとめます。例えば、不足するリンク1件を復元し、正常な22件を変更しなかった場合は次のようになります。

```text
✓ "/Users/you/links/example.txt" — created
  → "/Users/you/files/example.txt"

1 changed, 22 unchanged
```

`slink fix -n` では、書き込まずに同じ操作の予定を表示します。

```text
○ "/Users/you/links/example.txt" — would create
  → "/Users/you/files/example.txt"

1 change planned, 22 unchanged
```

- `fix -n` では、対象のリンクをすべて復元した後に、参照先へアクセスできるかを予測して表示します。
- `✓` は参照先の警告がない完了済み操作、`○` はプレビュー、`!` は参照先の警告または操作の失敗を示します。
- `changed` はリンクまたは登録を変更した件数、`unchanged` は変更不要だった件数です。失敗があれば、その件数も表示します。参照先の問題は別に数え、リンクの作成や復元自体の失敗とは区別します。

### TSV

スクリプトなどで処理する場合は `-o tsv` を使います。

```sh
slink list -o tsv
slink check -o tsv
slink scan -o tsv
```

出力はヘッダー付きで、1リンクにつき1行です。

| コマンド | 列の順序 |
| --- | --- |
| `list` | `LINK`, `TARGET` |
| `check` | `LINK`, `LINK_STATE`, `TARGET`, `TARGET_STATE`, `ACTUAL_TARGET`, `ACTUAL_TARGET_STATE` |
| `scan` | `MANAGEMENT`, `LINK`, `LINK_STATE`, `TARGET`, `TARGET_STATE`, `ACTUAL_TARGET`, `ACTUAL_TARGET_STATE` |

| 列 | 内容 |
| --- | --- |
| `MANAGEMENT` | 登録済みか未登録か |
| `LINK` | リンクの配置先 |
| `LINK_STATE` | 登録どおりのリンクがあるか |
| `TARGET` | 登録された参照先。`list` では保存された文字列、`check` と登録済みの `scan` では検証・正規化後の絶対パス |
| `TARGET_STATE` | 登録された参照先へアクセスできるか |
| `ACTUAL_TARGET` | 実際のリンクから読み取った参照先のパス。相対パスの場合もある |
| `ACTUAL_TARGET_STATE` | 実際のリンクの参照先へアクセスできるか |

- パスのセルは JSON 文字列で、値がないセルは空欄です。JSON 復号後の `list` の `LINK`・`TARGET` は保存された文字列と完全に一致し、`ACTUAL_TARGET` は symlink から読み取った文字列と完全に一致します。相対表記、`/./`、区切りの数、末尾の表記も保持します。
- `check`・`scan` の `LINK` と登録された `TARGET` には、上記の表示用整理を適用します。相対パスを参照するリンクを `adopt` した場合など、登録と一致するリンクでも `TARGET` と `ACTUAL_TARGET` の表記が異なることがあります。診断結果は表示文字列の比較ではなく状態の列で確認してください。
- 未登録の `scan` の行では、`LINK_STATE`・`TARGET`・`TARGET_STATE` は空欄になり、実際の参照先を `ACTUAL_TARGET` に表示します。
- 結果は標準出力（stdout）、エラーの理由は標準エラー出力（stderr）に出します。
- `ERROR` の独立したパス欄と `PENDING` の両パスにも、同じ表示用整理と引用を適用します。エラー理由は文章として扱い、パスの整理を行いません。

## 制約と復旧

- `-f` でも、通常ファイルやディレクトリをリンクに置き換えることはできません。また、自分自身を直接指すリンクは作成・復元できません。
- `~/B` がディレクトリを指すリンクの場合、`~/B` と、その中にある `~/B/C` などのリンクを同時に管理することはできません。`~/B` を管理するか、その配下のリンクを個別に管理するか、どちらかを選んでください。
- 管理ファイルやロック・復旧用ファイルと同じ場所には、リンクを配置できません。それらのファイルを含むディレクトリも、リンクとして管理できません。例えば、`~/.config/slink/links.toml` を使う場合、`~/.config/slink` 自体は管理対象にできません。パスは UTF-8 で表せる必要があります。
- 作成・削除・置換が中断した場合は、同じコマンドを同じ引数・オプションで再実行して復旧してください。`check` で未完了の操作を確認できます。復旧するまでは、別の変更操作を実行できません。
- 管理ファイルの隣にあるロック・復旧用ファイル（`links.toml.slink-lock`・`links.toml.slink-pending` など）や、一時的な `.slink-*` 復旧ディレクトリは、復旧が終わるまで削除しないでください。
- 複数のリンクを処理する際、一部が失敗しても、完了済みの変更は元に戻りません。

## 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 操作が完了。`check` では対象の全リンクが正常 |
| `1` | `check` が問題を検出、操作が失敗・競合、または `scan` が検査を完了できなかった |
| `2` | 引数・管理ファイルの不正、管理ファイルの利用不能、復旧の中断など |

- `list` は登録を読み込んで表示できれば `0` を返します。パスやリンクが正しいかどうかは `check` で確認してください。
- 作成・`fix` が成功すれば、参照先が存在しなくても `0` を返します。`check` はリンクや参照先に問題があれば `1`、管理ファイルの値が不正なら `2` を返します。
- `scan` は権限・I/O エラーには `1` を返しますが、参照先が存在しないリンクを見つけただけでは失敗にしません。`fix` で参照先が異なるリンクを `-f` なしで修復しようとした場合は `1` を返します。
