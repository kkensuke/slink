# パス表示の共通化設計

状態: 設計中。今回の作業は設計書の追加であり、以下の表示仕様はまだ実装していない。
調査対象: main `24d9295`、Draft PR #27 の既存実装 `46130e2`。

## 決定

表示が値に求める契約に基づき、次の2つの入口を使い分ける。

- `display_path(path)`: パス表記を表示用に整理し、引用符・エスケープを付ける。
- `quoted(text)`: 原文を整理せず、引用符・エスケープだけを付ける。

ホームディレクトリを `~` に省略する処理は廃止する。相対パスを絶対化せず、入力時の `~/` 展開や実際の名前に含まれる `~` は扱いを変えない。
表示用の整理は途中の `/./` と重複した区切りを対象とし、`..` と末尾の `/`・`/.` を保持する。
ファイルシステムにアクセスする `paths::normalize()` は表示には利用しない。

## 適用範囲

| 出力・フィールド | 処理 | 理由 |
|---|---|---|
| human の list / check / scan の link・target・expected・actual | `display_path` | 読むためのパス表記を統一する |
| human の未完了操作・操作結果・dry-run・復旧結果・親ディレクトリ | `display_path` | 同じ表示契約 |
| human の操作失敗の独立したパス欄・走査エラーの対象パス | `display_path` | 理由文と分離されたパス欄 |
| TSV の check / scan の LINK | `display_path` | リンク位置を表示する列 |
| TSV の check / 管理済み scan の TARGET | `display_path` | 検証・正規化後の期待値を表示する列 |
| TSV の ERROR の対象パス・PENDING のリンク位置 | `display_path` | 対象位置を表示する欄 |
| TSV の list の LINK / TARGET | `quoted` | 管理ファイルの登録文字列を取得する契約 |
| TSV の check / scan の ACTUAL_TARGET | `quoted` | symlink に記録された文字列を取得する契約 |
| 一般の理由文・エラー全文・不正入力の引用 | 既存のテキスト整形 | 文中のパスを推測して変更しない |
| --config / -c の出力 | 既存の引用符なしの絶対パス | コマンド置換で利用する値 |
| 管理ファイル・復旧情報・symlink・入力処理・比較処理 | 既存処理 | 表示用の整理をデータ処理に利用しない |

TSV の未管理 scan の TARGET は現在どおり空欄。ACTUAL_TARGET が実際の参照先を表す。
原文保持とは引用・エスケープを復号した値が元の文字列と一致することであり、無引用で出力することではない。

## 既存の共通処理を利用する場所

`render_diagnosis()`、`target_line()`、`MutationOutput::print_result()` の内部を変更し、
呼び出している各コマンドには表示ロジックを増やさない。
`display_link()`・`quoted_path()` と PR #27 の `display_target()` は `display_path()` に統合する。
`quoted()` 自体にパス整理を追加してはならない。

## 詳細化する項目

- ルート・先頭の区切り・先頭の ./・空文字・非 UTF-8 の扱い。
- 全呼び出し箇所、特に PENDING の target と一般エラーの境界。
- human と TSV で expected / actual の表記差が消える場合の診断契約。
- 変更ファイルと回帰テストの受け入れ条件。
